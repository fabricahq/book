Shaping is where you work out what to build and how, before you commit to building it. You need it for anything new, from a feature to a whole system. You can usually skip it for bug fixes and maintenance.

The term comes from Ryan Singer's [Shape Up](https://basecamp.com/shapeup). Singer shapes on paper because code used to be expensive. With agents, a working prototype costs about what a sketch did, so you can shape with real software.

Each shaping stage produces something:

| Stage    | Produces                                         |
| -------- | ------------------------------------------------ |
| Explore  | A prototype, and a clear vision of what to build |
| Design   | A tech stack and a high-level architecture       |
| Slice    | A sequence of small slices                       |
| Document | A written record of what shaping decided         |
